01 · Story

Why AST instead of plain text?

Searching a JavaScript file for strings can find text, but it does not reliably tell a tool whether that text is an import, declaration, function call, expression, or another language construct. An AST provides that structure.

The repository's learning path

The project starts by reading a JavaScript file with Node.js. Babel Parser converts that source into a tree. The code then walks the top-level program nodes and prints useful properties such as type, start, end, original source text, imported names and variable identifiers.

The transformation side goes one step further: @babel/types creates a real AST node, @babel/generator turns that node into JavaScript, and the node's source position can be used to insert the generated statement.

Think of the project as: read → parse → understand → generate → insert.

03 · Code story

The important scripts

These files show the repository's main concepts with very little code.

run.js — inspect nodes

import fs from "node:fs";
import { parse } from "@babel/parser";

const source = fs.readFileSync("./app.js", "utf8");

const ast = parse(source, {
  sourceType: "module"
});

for (const node of ast.program.body) {
  console.log({
    type: node.type,
    start: node.start,
    end: node.end,
    text: source.slice(node.start, node.end)
  });
}

toFile.js — save the AST

const ast = parse(source, {
  sourceType: "module"
});

fs.writeFileSync(
  "./ast-output.json",
  JSON.stringify(ast, null, 2),
  "utf8"
);

create.js — build a node

const newImport = t.importDeclaration(
  [
    t.importDefaultSpecifier(
      t.identifier("endpoints")
    )
  ],
  t.stringLiteral(inJsFileName)
);

const code = generate(newImport).code;

insert.js — use AST position

const statement = ast.program.body[1];

const insertPosition = statement.start;

const result =
  source.slice(0, insertPosition) +
  newLine +
  source.slice(insertPosition);

fs.writeFileSync(filePath, result);

06 · Versions

Why are there many version folders?

The repository is an evolving AST laboratory. The versions preserve different experiments and approaches.

v1
Foundation

Concrete AST-based insertion experiment using parsed statements and generated imports.

v2+
Exploration

Additional experiments around parsing and handling AST node structures.

v5
Inspection

Documented example of reading source, parsing it and printing extracted node information.

v10
Continuation

Later versioned work continues the exploration rather than replacing the learning history.

08 · The bigger idea

AST turns code into something a program can reason about.

Once JavaScript is represented as structured nodes, the same foundation can support code analysis, dependency inspection, documentation generation, refactoring, migration scripts, API route automation and other developer tools.
